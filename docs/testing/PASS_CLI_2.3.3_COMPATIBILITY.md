# Proton Pass CLI 2.3.3 compatibility

Audit date: 2026-08-27. Upstream reference: [`51a4c9b110a0ffe6e81f4f5d3877b9e5a0c24112`](https://github.com/protonpass/pass-cli/tree/51a4c9b110a0ffe6e81f4f5d3877b9e5a0c24112). Scope: the **47 existing MCP tools** and six existing item-template resources; no tools were added.

**Evidence boundary:** contracts below are derived from upstream Rust source and compared with this repository's implementation and fixture tests. Linked tests identify coverage, not a claim that this document's author ran them or that every accepted input was exercised. No live Proton CLI/vault calls were used. This is not live conformance certification, a backend audit, or proof of compatibility with later releases.

**Audit checks completed:** all 47 registrations match the inventory; all 44 input schemas convert through the installed SDK's object normalization and JSON-schema conversion; the remaining three tools have no input schema. Four reason fields are required and thirteen are optional. All six template key sets match the pinned Rust structs. These checks used source loaded in memory, emitted no files, and invoked no Proton CLI. Full acceptance-test results are recorded separately from this document.

## Shared boundary and policies

The [runner](../../src/pass-cli/runner.ts) forces JSON only for format-capable commands, preserves attachment output paths, and leaves child arguments after `--` untouched. Known named flags bind leading-hyphen values with equals syntax so their contents remain data; this also protects literal `--output` and `--` values. It writes template input to child stdin and closes the pipe. Some legacy `output` inputs remain accepted; the [MCP output policy](../adr/ADR-001-mcp-output-format-boundary.md) controls their effective format.

In the inventory, `scope` means one share-ID or vault-name selector; `selector` means one item-ID or item-title selector. Explicit selectors and schema bounds may be narrower than upstream. Omitted scope uses the configured default vault only where that existing tool allows omission. The [write gate](../../src/tools/shared/write-gate.ts) requires both `ALLOW_WRITE=1` and `confirm: true`; it now also covers attachment download.

**Reason column:** Required means `agentReason` is mandatory for all session types and checked before CLI dispatch; Optional means the input is optional at the MCP boundary but required by upstream during agent sessions; — means no reason field was added. Four tools are Required and thirteen are Optional. [Reason tests][test-reason] exercise forwarding, Unicode length, and rejection before dispatch; [runner tests][test-helpers] exercise separate child environments and stdin.

## Agent and failure semantics

Upstream validates `PROTON_PASS_AGENT_REASON` as nonblank and at most 300 Unicode scalar values. The wrapper counts code points, preserves the supplied text, and forwards it per child invocation; it does not invent a reason or mutate shared environment state. [Upstream helper][agentMonitor], [limit][monitor], [local implementation](../../src/tools/shared/agent-reason.ts)

The four Required rows correspond to upstream operations that mutate before validating/sending a reason. Requiring the input in every session avoids brittle detection: `info` has no stable account-type field, only an `[Agent] ` display prefix in a token name. A valid reason does not make the operation transactional: a subsequent monitor/network failure may still occur after a successful change. Do not automatically retry these failures. [Account output][info], [internal mode flag][infoLibrary]

Other existing operations do not all use the same CLI reason hook. Its absence is not proof that backend logging is absent or that agent permissions allow the operation. Upstream restricts vault creation/deletion/sharing and invite management for PAT/agent sessions. Authentication remains managed outside MCP; do not attempt automatic login, unlock, token conversion, or account probes. [Capability guards][permissions]

## Remaining limitations

- **Protocol input shape:** object-input tools expect an `arguments` object. Invitation pagination now publishes its optional fields correctly, with `arguments: {}` replacing an omitted arguments property for empty MCP requests. The [protocol regression][test-setup] checks every input tool's published fields and empty invitation input.
- **Argument-policy maintenance:** any future required-value flag must be included in the runner's named-value registry and regression coverage. The current registry covers the existing surface; it intentionally stops before the child-command delimiter.
- **Permission diagnostics:** generic `forbidden` no longer triggers re-login guidance; explicit authentication failures still do. Error classification remains a text heuristic because the CLI does not provide a stable structured error protocol. [Classifier tests][test-helpers]
- **Upstream limits:** password generator behavior in its external implementation, account-plan restrictions, locked/expired sessions, and actual backend response variation are not established by these fixture checks. Run output masking is best effort, not a guarantee that all secrets are redacted. [Generator delegation][passwordLibrary], [masking][runMasking]
- **Local writes:** attachment confirmation authorizes a write that may overwrite the chosen path; it does not provide exclusive-create semantics. Inspect the path before approving. [Download implementation][attachment]
- **Evidence still required:** a separately authorized live integration check is deferred under the repository's safety constraint. The [test plan](CODEX_MCP_TEST_PLAN.md) and [upstream drift workflow](../upstream/README.md) remain the follow-up references.
